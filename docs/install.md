# Установка GamayunNas

[English](install.en.md) · [README](../README.md)

Инструкция ведёт от чистого компьютера до работающего NAS: подготовка Debian, установка пакетов,
мастер первого запуска, первый пул, доступ по сети. В конце — обновление, удаление, перенос пулов
и диагностика.

## 1. Требования

| | Минимум | Рекомендуется |
|---|---|---|
| Система | Debian 13 (trixie), amd64 | Debian 13, установка без графического окружения |
| Процессор | 2 ядра x86-64 | 4 ядра |
| Память | 2 ГБ | 4 ГБ и больше (8 ГБ — с приложениями Docker) |
| Системный диск | 16 ГБ, отдельный от дисков данных | SSD 32 ГБ и больше |
| Диски данных | 1 | 2 и больше — для RAID; одинаковой ёмкости не обязательно (SHR) |
| Сеть | Ethernet, постоянный адрес (DHCP-резервирование или статический) | 1 Гбит/с и быстрее |

> **Диски данных будут полностью переразмечены** при создании пула. GamayunNas не трогает диски
> с разделами или данными и не предлагает их для нового пула, но перед установкой всё равно
> проверьте, что на выбранных дисках нет нужного.

Порты: **8780/tcp** — веб-интерфейс (HTTPS), **445/tcp** — SMB, **22/tcp** — SSH (если включён),
**443/tcp** — веб-адреса приложений (если опубликованы), **5353/udp** — mDNS (имена `*.local`).

## 2. Подготовка Debian

1. Установите Debian 13 на **системный диск** с обычного установочного образа (netinst).
   На шаге выбора программ оставьте только **SSH server** и **standard system utilities**.
   Диски данных при установке не размечайте.
2. Войдите в систему и обновите её:
   ```sh
   sudo apt update && sudo apt full-upgrade -y
   ```
3. Задайте серверу постоянный адрес (резервирование на роутере или статический адрес
   в `/etc/network/interfaces`).
4. Проверьте, что диски данных видны и пусты:
   ```sh
   lsblk -o NAME,SIZE,TYPE,MODEL,SERIAL,MOUNTPOINTS
   ```

## 3. Установка пакетов

Скачайте пакеты со страницы **Releases** репозитория:

- `gamayun-nas_<версия>_amd64.deb` — сам NAS (обязательно);
- `gamayun-nas-apps_<версия>_amd64.deb` — приложения Docker (по желанию; несовместим с `docker-ce`
  и `docker.io` из других источников);
- `SHA256SUMS` — контрольные суммы.

```sh
sha256sum -c SHA256SUMS --ignore-missing
sudo apt install ./gamayun-nas_*_amd64.deb
# по желанию:
sudo apt install ./gamayun-nas-apps_*_amd64.deb
```

`apt` сам поставит зависимости (Samba, mdadm, LVM, Btrfs, smartmontools, fail2ban и др.).
После установки запущены службы `gamayund`, `gamayun-helper` и `gamayun-integrity`:

```sh
systemctl status gamayund gamayun-helper --no-pager
```

> Пакет дополняет `/etc/samba/smb.conf` (копия исходного — `/etc/samba/smb.conf.pre-gamayun`)
> и подменяет `/etc/logrotate.d/fail2ban`, чтобы ротация журналов не падала при выключенной
> защите SSH. При удалении пакета штатный файл возвращается.

## 4. Первый вход и мастер

1. Узнайте токен первого входа:
   ```sh
   sudo cat /var/lib/gamayun-nas/setup-token
   ```
2. Откройте в браузере `https://<адрес-сервера>:8780/`. Сертификат самоподписанный — браузер
   предупредит об этом; подтвердите переход. Свой сертификат можно загрузить позже:
   **Настройки → Сертификат HTTPS**.
3. Введите токен, придумайте имя и пароль администратора (не короче 10 символов).
4. Мастер предложит:
   - **восстановить настройки из копии** — если вы переносите NAS (см. [раздел 10](#10-переустановка-системы-и-перенос-пулов));
   - задать **имя сервера** и **часовой пояс**;
   - создать **первый пул** или подключить **найденный** на дисках.
5. После мастера открывается главная страница. Токен больше не действует.

Забыли пароль администратора — смените его с консоли сервера:

```sh
sudo -u gamayun /usr/lib/gamayun-nas/gamayund admin passwd -name <имя>
```

## 5. Доступ по SSH после мастера

По умолчанию после мастера **служба SSH выключена**, а вход под `root` и системными учётками
(например, `debian`) закрыт. Уже открытые сессии не рвутся.

Если сервером нужно управлять по SSH:

1. **Пользователи** — создайте пользователя (или откройте существующего) и включите
   **Вход по SSH**. У администраторов NAS он включён по умолчанию, и только они получают `sudo`.
2. **Настройки → Служба SSH → Включить.**
3. Входите под этим пользователем с его паролем NAS:
   ```sh
   ssh <пользователь>@<адрес-сервера>
   ```

Защита от перебора паролей (fail2ban) настраивается там же, в блоке **Защита SSH от перебора паролей**.

<details>
<summary>Для администратора: вход по ключу под root</summary>

Для тестовых серверов можно оставить вход по ключу для отдельных системных учёток (пароли для них
всё равно запрещены). Добавьте их в `/etc/gamayun-nas/gamayun-helper.json`:

```json
{ "mount_root": "/srv/gamayun-nas", "destructive_allow_ids": [], "ssh_dev_access": ["root"] }
```

и перезапустите helper: `sudo systemctl restart gamayun-helper`. Делайте это **до** завершения
мастера, если управляете сервером по SSH под root.

</details>

## 6. Первый пул и общие папки

1. **Хранилище → Пулы → Создать пул.** Выберите диски и схему. Для двух и более дисков
   разного размера подходит **SHR** (один диск может отказать) или **SHR-2** (два).
   **Контроль целостности** включён по умолчанию — оставьте его.
2. Проверьте план: какие диски будут размечены, сколько места получится. Подтвердите вводом имени пула.
3. Пул сразу доступен для записи; начальная синхронизация RAID идёт в фоне и видна в карточке пула.
4. **Общие папки → Создать:** имя, пул, права пользователей и групп.
5. Подключение по сети:
   - Windows: `\\<имя-сервера>\<папка>` или `\\<адрес>\<папка>`;
   - macOS: Finder → **Подключение к серверу** → `smb://<адрес>/<папка>`;
   - Linux: `smb://<адрес>/<папка>` в файловом менеджере.
   Вход — именем и паролем пользователя NAS.
6. **Общие папки → Снимки** — расписание снимков; восстановление — из карточки папки или через
   **Предыдущие версии** в Windows.

Пулы монтируются в `/srv/gamayun-nas/<пул>`.

## 7. Приложения Docker

> **В разработке.** Работает, но интерфейс и формат могут меняться между версиями alpha.

Нужен пакет `gamayun-nas-apps`.

1. **Приложения** — выберите пул и включите приложения. Docker хранит образы и данные на нём (`<пул>/.apps`).
2. **Добавить приложение** — вставьте docker compose. Система покажет риски (привилегии, порты,
   доступ к папкам) и попросит подтверждение.
3. **Веб-адрес** в карточке приложения публикует его как `https://<приложение>-<имя-NAS>.local/`.
   Чтобы браузер доверял адресу, установите на устройства **корневой сертификат NAS** (ссылка в той
   же карточке). Порт 443 должен быть свободен.

## 8. Обновление

Скачайте новые пакеты и установите их **одной командой** (если стоят оба):

```sh
sudo apt install ./gamayun-nas_*_amd64.deb ./gamayun-nas-apps_*_amd64.deb
```

Службы перезапускаются автоматически, настройки и пулы сохраняются. Перед обновлением рекомендуется
сохранить копию настроек: **Настройки → Резервная копия → Сохранить в пулы сейчас**.

Alpha обновляется только пакетом: автоматического отката нет. Чтобы вернуться на прежнюю версию,
установите её пакет тем же способом.

## 9. Удаление

```sh
sudo apt remove gamayun-nas-apps gamayun-nas     # службы удалены, настройки и пулы сохранены
sudo apt purge gamayun-nas-apps gamayun-nas      # плюс конфигурация в /etc/gamayun-nas
```

Ни `remove`, ни `purge` **не удаляют** базу настроек (`/var/lib/gamayun-nas`), каталог пулов
(`/srv/gamayun-nas`) и данные на дисках. Чтобы стереть всё, удалите пулы в веб-интерфейсе до
удаления пакета.

## 10. Переустановка системы и перенос пулов

Пулы хранят описание своего состава и копии настроек на самих дисках. Поэтому после переустановки
Debian или переноса дисков в другой компьютер:

1. Установите Debian 13 и пакет GamayunNas ([разделы 2–3](#2-подготовка-debian)). Подключите все
   диски пулов.
2. В мастере (или в **Хранилище → Пулы**) появится карточка **Найденные пулы**. Введите имя пула
   и нажмите **Подключить** — тип, уровни RAID и контроль целостности берутся с дисков.
3. Если найдены не все диски, пул подключается только после отдельной галочки и работает
   неполным; вернувшийся диск войдёт в массив сам.
4. Мастер предложит **восстановить настройки** из копии на пуле: пользователи, группы, общие папки,
   права, расписания. Пароли пользователей задаются заново.

Копии настроек сохраняются на каждый пул автоматически (раз в час, если настройки менялись); их также
можно хранить по SFTP, записывать на USB-носитель или скачивать файлом (**Настройки → Резервная копия**).

## 11. Диагностика

| Что проверить | Команда |
|---|---|
| Состояние служб | `systemctl status gamayund gamayun-helper gamayun-integrity` |
| Журнал демона | `journalctl -u gamayund -b` |
| Журнал операций с дисками | `journalctl -u gamayun-helper -b` |
| Массивы RAID | `cat /proc/mdstat` |
| Тома и пулы | `lsblk`, `sudo lvs`, `findmnt -t btrfs` |
| Конфигурация | `/etc/gamayun-nas/gamayund.json`, `/etc/gamayun-nas/gamayun-helper.json` |

Частые ситуации:

- **Страница не открывается.** Проверьте, что `gamayund` запущен и слушает порт:
  `sudo ss -tlnp | grep 8780`. Адрес — именно `https://`.
- **Вход заблокирован после неверных паролей.** Подождите снятия блокировки или выполните
  `sudo systemctl restart gamayund`.
- **Пул «только для чтения».** Откройте карточку пула: там причина (выбыл диск, ошибка записи)
  и что делать. Подробно — во встроенной справке (кнопка **?**).
- **Диск не предлагается для пула.** На нём есть разделы или сигнатуры файловых систем. Если данные
  на нём не нужны, очистите его вручную (`sudo wipefs -a /dev/sdX` — **необратимо**).

Встроенная справка (кнопка **?** в каждом окне) подробно описывает состояния пулов, дисков
и приложений.
