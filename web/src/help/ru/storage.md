# Хранилище

Хранилище — место, где NAS держит ваши данные: физические **диски** и **пулы**, собранные из них.
Пул — несколько дисков, объединённых в одно хранилище: снаружи это одно место для общих папок,
а внутри данные разложены по дискам так, чтобы пережить отказ одного или двух из них.
Как кладовка с несколькими полками: вещи лежат на разных полках, а вы видите одну кладовку.

## Что вы видите
Окно **Хранилище** состоит из двух вкладок:
- **Пулы** — список пулов: имя, схема, число дисков, отметка «контроль целостности» и состояние.
  Кнопка **Создать пул** запускает мастер. Нажмите на пул — откроется его карточка.
- **Диски** — все диски NAS: свободные, системные и уже занятые в пулах, с итогом SMART.
  Подробнее — [Диски](help:storage.disks).
- **Найденные пулы** — появляются, если на подключённых дисках есть пул, которого эта система
  ещё не знает (например, после переустановки). См. [Найденные пулы](help:storage.pools.found).

## Состояние пула
| Состояние | Что значит |
|---|---|
| **Исправен** | всё в порядке |
| **Синхронизация** | пул только что создан, диски сверяются; до конца синхронизации защита неполная |
| **Восстановление** | идёт восстановление избыточности после выбытия диска |
| **Перестройка** | меняется раскладка данных по дискам |
| **Неполный (диск выбыл)** | диск пула отказал или отключился — см. [Пул неполный](help:storage.pools.incomplete) |
| **Только чтение (ошибка записи)** | пул аварийно перестал принимать запись — см. [Пул только для чтения](help:storage.pools.readonly) |
| **Отказ** | пул не работает — как правило, выбыло больше дисков, чем выдерживает схема |
| **Диски не найдены** | дисков пула нет в системе |
| **Состояние не определено** | система не смогла прочитать состояние пула |

Если с пулом что-то не так, на главной появляется строка с кнопкой **Открыть**, а в карточке пула —
блок **Что происходит** с пояснениями.

## Типы пулов
Схема (уровень RAID) задаёт, сколько места останется для файлов и сколько дисков может отказать без
потери данных. Коротко:
- **Basic, JBOD, RAID 0** — без запаса: отказ любого диска может стоить данных пула.
- **RAID 1** — зеркало: одинаковые копии на всех дисках.
- **RAID 5 / SHR** — переживёт отказ одного диска; **RAID 6 / SHR-2** — двух.
- **RAID 10** — пары зеркал; один отказ переживёт наверняка.
- **SHR и SHR-2** лучше используют диски разного размера.

Подробно, с таблицей и советами по выбору — [Пул и уровни RAID](help:storage.pools.raid).

## Целостность данных
- **Контроль целостности** — отметка в мастере создания пула (включена по умолчанию). К каждому блоку
  данных добавляется контрольная сумма, и тихая порча на диске обнаруживается при чтении. Запись
  при этом медленнее.
- **Проверка данных** — периодически читает все копии данных пула и исправляет ошибки чтения.
  По умолчанию идёт раз в 30 дней ночью, расписание — в **Настройках**. См. [Проверка пула](help:storage.pools.scrub).
- **Защита при исчерпании избыточности** — когда отказ ещё одного диска приведёт к потере данных,
  пул сам переходит в режим только чтения. См. [Пул только для чтения](help:storage.pools.readonly).

## Карточка пула
Здесь собрано всё про один пул: состояние и массивы RAID, ход синхронизации, **Проверка данных**,
**Запись на пул**, **Защита при исчерпании избыточности**, **Журнал защиты** и **Удаление пула**.

## Чего не делать
- **Удалить пул** стирает все его данные без возможности восстановления. Сначала заберите нужное.
- Не вынимайте диски работающего пула «на проверку»: для пула без запаса это потеря данных.
- RAID защищает от отказа диска, но не от удаления файлов и шифровальщиков: держите резервную копию
  важного на другом устройстве и включите снимки общих папок.

См. также: [Пул и уровни RAID](help:storage.pools.raid), [Диски](help:storage.disks),
[Найденные пулы](help:storage.pools.found), [Проверка пула](help:storage.pools.scrub).
