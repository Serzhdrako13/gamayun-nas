# Риски

Некоторые настройки compose дают приложению больше власти, чем ему обычно нужно. Это не всегда
ошибка: например, медиасерверу нужна видеокарта. Поэтому такие настройки не запрещены, но каждую
нужно подтвердить отдельной галочкой. В журнал записывается, кто и когда подтвердил какой риск.

## Что вы видите
Блок **Риски — подтвердите каждый** в мастере и **Подтверждённые риски** в карточке приложения.

| Риск | Что значит |
|---|---|
| полный доступ к системе NAS (privileged) | приложение может всё, что может администратор NAS |
| доступ к управлению Docker (docker.sock) | приложение может запускать любые контейнеры — это те же права администратора |
| сеть NAS напрямую (network_mode: host) | приложение видит все сетевые службы NAS и занимает порты без проверки |
| процессы, память, имя узла NAS (pid, ipc, uts: host), без изоляции пользователей | приложение видит и может затронуть программы NAS |
| дополнительные права ядра (cap_add) | расширенные права внутри системы |
| прямой доступ к устройствам NAS (devices, gpus) | например, к диску или видеокарте |
| отключена защита ядра (unconfined) | снимаются ограничения, которые сдерживают взломанное приложение |
| сервис работает как root и может менять файлы в общей папке | для режима «как root» с записью в папку: права на папку его не сдерживают |
| доступ к общей папке с правами root | только у приложений, добавленных до учёток приложений; переведите их на свою учётку |
| порт открыт для всей сети | см. ниже |

**Порт открыт для всей сети.** Опубликованный порт Docker проходит **мимо фаервола NAS**: к нему
сможет подключиться любой компьютер вашей сети. Включайте **доступно в сети**, только если
приложением пользуются с других устройств, и задайте в нём пароль.

## Что делать
1. Прочитайте каждый риск и спросите себя, зачем он этому приложению. Ответ обычно есть в описании
   программы.
2. Не уверены — не подтверждайте: уберите строку из compose и нажмите **Проверить** ещё раз.

## Чего не делать
- Не подтверждайте риски «пачкой», не читая: приложение с доступом к Docker или с privileged,
  если его взломают, получит весь NAS вместе с данными.

См. также: [Добавить приложение](help:apps.add), [Учётка и доступ к папкам](help:apps.access), [Порты](help:apps.ports).
