# Порты

Порт — номер «двери» NAS, через которую программа принимает подключения по сети. У одной двери
может быть только один хозяин: если её уже занял NAS или другое приложение, второе туда не встанет.

## Что вы видите
Вкладка **Порты** — таблица **Порт**, **Кто занимает**, **Доступ**:
- **служба NAS** — порты самого NAS (SSH 22, веб-интерфейс 80 и 443, SMB 139 и 445, NFS 2049,
  mDNS 5353 и другие). Приложениям они не выдаются никогда;
- **приложение** — порт, указанный в compose, с доступом **только на NAS** или **в сети**;
- **занят на NAS** — порт слушает другая программа.

## Как это работает
1. По умолчанию порт приложения доступен **только на NAS** (адрес 127.0.0.1): с других устройств
   к нему не подключиться. Это безопасно, пока вход через общий адрес NAS не готов.
2. Отметка **доступно в сети** в мастере открывает порт для всей сети. Опубликованный порт Docker
   проходит **мимо фаервола NAS** — это [риск](help:apps.risks), его нужно подтвердить.
3. При проверке compose занятые порты показываются в блоке **Конфликты портов**; создать приложение
   с конфликтом нельзя.

## Что делать
Конфликт — поменяйте в compose номер слева: `8081:80` вместо `8080:80` (слева — порт NAS, справа —
порт внутри контейнера), затем **Проверить**.

См. также: [Добавить приложение](help:apps.add).

:::details Для администратора
Занятые порты NAS определяет по `/proc/net/tcp`, `tcp6`, `udp`, `udp6`. Docker публикует порты
своими правилами nftables в обход входной цепочки фаервола NAS — поэтому «доступно в сети» считается
риском.
:::
