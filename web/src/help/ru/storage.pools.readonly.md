# Пул только для чтения

Иногда система сама запрещает запись на пул: файлы можно открывать и копировать к себе, но нельзя
создавать, менять и удалять. Так она поступает, когда **запас избыточности исчерпан** — отказ ещё
одного диска приведёт к потере данных. Избыточность — запасная копия данных на других дисках пула.
Это как перестать грузить вещи в лодку, которая уже набрала воды: сначала спасти то, что есть.

Бывает и второй случай — **аварийный**: запись на диск не удалась, и файловая система пула сама
перестала принимать запись, чтобы не испортить уже записанное. Об этом — глава
«Аварийно только для чтения (ошибка записи)» ниже.

## Что вы видите
- Баннер «Пул переведён в режим только чтения: запас избыточности исчерпан» или текст о
  конкретном массиве RAID пула («… неполный (выбыл диск): отказ ещё одного диска приведёт к потере
  данных»). Он есть на главной, в списке пулов и в карточке пула.
- В карточке пула, блок **Запись на пул** — пояснение, поля **Причина (обязательно)** и **Срок**,
  кнопка **Разрешить запись на срок**.
- Общие папки на этом пуле по сети тоже доступны только для чтения.
- Если запись разрешена вручную — баннер «Запись временно разрешена вручную до …», в блоке
  **Запись на пул** видно, кто разрешил, с какой причиной и до какого времени.
- Ниже — **Журнал защиты**: кто и когда переводил пул в режим только чтения или разрешал запись.

## Как это работает
1. Система постоянно следит за массивами пула. Как только запас исчерпан, пул перемонтируется только
   для чтения — без вашего участия.
2. Когда запас восстановлен (например, после восстановления избыточности), запись возвращается сама.
3. Разрешение записи вручную действует до конца выбранного срока. Если к этому времени запас не
   восстановлен, пул снова станет только для чтения.

## Аварийно только для чтения (ошибка записи)
Если диск пула отказал при записи, файловая система пула сама переходит в режим только чтения. Диски
и массивы при этом могут выглядеть исправными — отказ был в момент записи.
- Состояние пула — **Только чтение (ошибка записи)**, пул попадает в «Требуют внимания» на главной.
- Баннер «Файловая система пула аварийно перешла в режим только чтения после ошибки записи».
- В карточке пула, блок **Что происходит** — строка «Btrfs аварийно перешёл в режим только для чтения
  после ошибки записи…».
- В журнале событий и уведомлениях — «Пул аварийно перешёл в режим только для чтения», после
  восстановления — «Пул снова доступен для записи».
- **Разрешить запись на срок** здесь не предлагается: запрет поставила не защита, кнопка не поможет.

Что делать:
1. **Заберите важные данные** — чтение работает.
2. Проверьте диски: раздел «Диски», данные SMART, журнал событий.
3. Сам режим не снимется: пул нужно перемонтировать (отключить и снова подключить файловую систему).
   Кнопки для этого пока нет — обратитесь к администратору сервера. Если диск неисправен, сначала
   замените его, иначе запись снова отключится.

## Что делать
1. **Заберите важные данные** — чтение работает. Это первый шаг.
2. Выясните причину — обычно это [выбывший диск](help:storage.pools.incomplete).
3. Если запись нужна срочно (например, программа не умеет работать с папкой только для чтения):
   в блоке **Запись на пул** напишите причину, выберите срок (от **15 минут** до **7 дней (максимум)**)
   и нажмите **Разрешить запись на срок**. При следующем отказе диска записанное за это время может
   пропасть.
4. Закончили — нажмите **Снять разрешение сейчас**, не дожидаясь конца срока.

## Выключить защиту (только предупреждать)
Бывает, что остановка записи вредит больше, чем риск: служба или программа должна срочно дописать или
восстановить данные, а с пулом только для чтения она стоит. Для такого случая защиту можно выключить.
Это как продолжать плыть на лодке, которая набрала воды, потому что до берега нужно добраться сейчас.

Чем рискуете: если запас избыточности исчерпан и откажет ещё один диск, **данные пула будут потеряны** —
и старые, и всё, что записано после выбытия диска.

1. Карточка пула, блок **Защита при исчерпании избыточности**.
2. Выберите **Только предупреждать**. Появится предупреждение о риске и поле **Причина (обязательно,
   попадёт в журнал)**.
3. Напишите причину и нажмите **Понимаю риск, выключить защиту**. Если пул в этот момент уже был только
   для чтения из-за защиты, запись вернётся сразу.
4. Пока защита выключена, на главной и в карточке пула висит баннер «Защита пула выключена…». Если запас
   исчерпан — баннер красный, а в журнале событий и уведомлениях появляется «Запас избыточности
   исчерпан, защита пула выключена — пул остаётся на запись».
5. Закончили срочную работу — выберите **Переводить в только чтение (рекомендуется)**, напишите
   причину и нажмите **Включить защиту**. Если запас всё ещё исчерпан, пул сразу перейдёт в режим только
   чтения.

Кто, когда и с какой причиной выключал и включал защиту — в **Журнале защиты**.

Выключатель не помогает при **аварийном** режиме только чтения (ошибка записи): его поставила сама
файловая система, а не защита. Об этом — глава выше.

Если запись нужна ненадолго, лучше **Разрешить запись на срок**: разрешение снимется само.

## Чего не делать
- Не держите запись разрешённой «на всякий случай»: защита для того и включилась, чтобы новые файлы не
  легли на пул, который может потерять данные.
- Не оставляйте защиту выключенной после срочной работы: баннер на главной об этом напоминает.
- Не пытайтесь «починить» пул удалением и созданием заново: **Удалить пул** стирает все данные без
  возможности восстановления.

См. также: [Пул неполный (диск выбыл)](help:storage.pools.incomplete), [Пул и уровни RAID](help:storage.pools.raid).

:::details Для администратора
Защита перемонтирует файловую систему пула (`mount -o remount,ro`) и переводит общие папки пула в
режим только чтения; проверка идёт по таймеру и сразу при изменении `/proc/mdstat`. Аварийный режим
ставит ядро после ошибки записи Btrfs: подробности — `journalctl -k | grep -i btrfs`. Снимается он только
отключением и повторным подключением файловой системы пула; кнопки для этого пока нет.
:::
